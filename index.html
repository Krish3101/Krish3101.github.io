Selected work

Five projects. Each one runs from a clone.

01

geoagent

Python · pydantic-ai Ask for GIS data in plain language and get back real GeoJSON, GeoPackage and GeoTIFF files.
The problem
A language model is fluent enough to invent a plausible bounding box, and downstream a wrong coordinate looks exactly like a right one.
The decision
The model chooses which tool to call and nothing else. Coordinates and file paths live in the run context, never in the model’s output, so every calculation happens in Python and the model only ever selects.
Stack
pydantic-ai, FastAPI, GeoPandas, OSMnx and SQLite. Boundaries come from OpenStreetMap and imagery from Planetary Computer Sentinel-2; progress streams back over server-sent events. Geocoding is throttled to one request a second to stay inside the Nominatim usage policy.
Running it
./scripts/start.sh on port 8000. Tests are uv run pytest -q; the ones that need network are deselected unless you pass -m network.

02

farmland

Python · PostGIS Turns a messy farmland spreadsheet into validated field boundaries, served as RFC 7946 GeoJSON.
The problem
Field boundaries arrive as spreadsheet text: inconsistent coordinate order, malformed polygons, duplicate vertices. Cleaning all of that on every read would make every read slow.
The decision
The cleaning happens in PostGIS when the materialised view refreshes, not when a request arrives. A read is then an indexed lookup on geometry that has already been validated.
Stack
FastAPI, SQLAlchemy, asyncpg and Pydantic over PostGIS, brought up with Docker Compose. Requests authenticate with an X-API-Key header.
Running it
./scripts/start.sh on port 8000 — it starts Postgres and ingests the sample data. ./scripts/reset.sh tears the volume back down. Tests are uv run pytest, and the Postgres ones skip rather than fail without a live database.

03

trafficengine

Java · Spring Boot Takes a vehicle speed reading, decides whether it is a violation, and computes the fine.
The problem
Penalty policy changes more often than the software that applies it. Encoding speed limits and fine tiers in Java means a code change and a redeploy for every revision.
The decision
The limits and the fine tiers are configured under traffic.rules in application.yml. The engine itself is plain Java with no Spring and no database in it, so the rules can be tested without starting either.
Stack
Java 21, Spring Boot 3.4 and Spring Data JPA over an in-memory H2 database. The Maven wrapper is committed, so it builds without Maven installed.
Running it
./scripts/start.sh on port 8080. Tests are ./mvnw test — unit tests on the engine, MockMvc tests on the API.

04

text-to-sql

Python · sqlglot Ask a question in English, get a SQLite query, and run it against a bundled sample database.
The problem
A generated query is untrusted input that happens to look like SQL. Checking it by matching strings fails as soon as the same statement is phrased a little differently.
The decision
Every query is parsed into a syntax tree before it runs and classified from that tree rather than from its text. Reads open on a read-only connection; anything that writes needs explicit approval first.
Stack
Streamlit, sqlglot, SQLAlchemy and pandas, with the model called over OpenRouter through urllib.
Running it
./scripts/start.sh on port 8501. Tests are pytest tests/ -v.

Source on GitHub

05

disputeledger

TypeScript · Express Tracks commercial disputes between supply chain partners, with an audit trail that cannot be quietly edited.
The problem
An audit log kept as ordinary rows is only as trustworthy as the database holding it. Anyone with write access can rewrite history and leave nothing behind to show it.
The decision
Every change appends an event carrying the previous event’s hash. Verification walks the chain and recomputes each hash in turn, so a row edited directly in SQLite breaks the link rather than passing quietly.
Stack
TypeScript run straight through tsx with no build step, Express, better-sqlite3 and Zod. Passwords go through scrypt. The frontend is plain HTML, CSS and ES modules.
Running it
./scripts/start.sh on port 3000. Tests are npm test, running under Vitest.

About

I prefer systems whose behaviour you can work out on paper. That preference shows up the same way each time: the part that decides something is separated from the part that talks to the network, so it can be read and tested on its own.

It is why the rule engine has no Spring in it, why the geospatial work happens in PostGIS rather than in Python, and why the projects that use a language model still do all of their arithmetic without one.
